## Audit Criteria

Primary criteria came from `AGENTS.md` and the project's ADRs:

- No hidden cloud calls, cloud API clients, model download logic, secrets, or telemetry.
- The only sanctioned external network call is the quant advisor's explicit
  `--lookup-hf` public Hugging Face metadata lookup.
- Dashboard render paths must not make external/network calls; inline no-src JS only.
- Default `/ask` response must stay privacy-narrow: no `retrieved_chunks`,
  `source_path`, or `preview` by default.
- Runtime service binds and configured provider URLs must remain loopback-only.
- Destructive model removal must be disabled by default, two-step confirmed,
  action-token gated, path-contained, and recoverable/controlled.
- Benchmark execution must be approval-gated before any model call.
- CSV exports/imports must neutralize spreadsheet formulas; artifact paths must
  prevent traversal.
- Logs must not dump documents, prompts, retrieved chunks, API keys, or private
  paths by default.

## Findings Requiring Remediation

### SEC-001 - Benchmark CLI capture logs duplicate model stdout/stderr

Severity: Medium  
Type: True positive  
Affected files: `evals/local-llm-benchmark/harness.py`

Evidence:

- `run_llama_cpp` stores `raw_response` in `raw_responses.jsonl` at
  `evals/local-llm-benchmark/harness.py:1251`, then also writes raw stdout and
  stderr into `llama-cpp-capture.log` at `1255-1271`.
- `run_mlx_lm` stores `raw_response` in `raw_responses.jsonl` at
  `evals/local-llm-benchmark/harness.py:1346`, then also writes raw stdout and
  stderr into `mlx-lm-capture.log` at `1350-1366`.
- `run_lmstudio_cli` stores `raw_response` in `raw_responses.jsonl` at
  `evals/local-llm-benchmark/harness.py:1436`, then also writes raw stdout and
  stderr into `lms-cli-capture.log` at `1440-1453`.
- The Ollama runner is narrower: `evals/local-llm-benchmark/harness.py:1173-1185`
  writes latency/token/error metadata but not raw response text to its capture log.

Impact:

The benchmark harness intentionally writes raw model responses to
`raw_responses.jsonl`, but duplicating raw stdout/stderr into `.log` files
increases accidental disclosure risk when users share logs as validation
evidence. Because prompts and model outputs may contain private local data, this
conflicts with the project's default logging invariant even though the artifacts
are repo-local and documented.

Recommended remediation:

- Keep `raw_responses.jsonl` as the explicit raw-output artifact.
- Change `llama-cpp-capture.log`, `mlx-lm-capture.log`, and
  `lms-cli-capture.log` to metadata-only logs: prompt ID, return code, latency,
  token counts, stop reason, and sanitized/truncated error summaries.
- Do not write raw stdout/stderr to `.log` files by default. If full raw CLI
  stdout/stderr is still needed, gate it behind an explicit flag with clear naming.
- Update benchmark README/spec/lab notes and tests.
- ADR 0010 is probably not required if the fix only narrows log contents while
  preserving `raw_responses.jsonl`; reserve ADR 0010 only if the artifact contract
  changes materially.

### SEC-002 - Resolved Starlette version has dependency advisories

Severity: Medium  
Type: True positive, low current exposure  
Affected dependency: `starlette 1.1.0` resolved through FastAPI

Evidence:

- `pip-audit` reported:
  - `CVE-2026-54283`, fixed in `starlette 1.3.1`, urlencoded form parsing DoS.
  - `CVE-2026-54282`, fixed in `starlette 1.3.0`, request URL authority boundary.
- Runtime version check showed `starlette 1.1.0`.
- The current FastAPI app exposes `/health` and JSON `/ask` and does not call
  `request.form()` or make security decisions from `request.url`, so the immediate
  app exposure appears low.

Impact:

This is still a real dependency hygiene issue for the local FastAPI server. A
future route or middleware could accidentally exercise vulnerable behavior.

Recommended remediation:

- Upgrade FastAPI/Starlette constraints and lockfile to a compatible set resolving
  `starlette >=1.3.1`.
- Run the full project validation gate after the upgrade.
- If FastAPI has not yet released a compatible constraint, document the accepted
  local-only risk and revisit on the next dependency refresh.

- `src/local_ai_lab/cli/quant_advisor.py:152`: accepted sanctioned behavior. It is

  model download, or registration side effect.

### Bandit subprocess findings

Bandit reported subprocess imports/calls in dashboard removal, smoke checks,
hardware inspection, and benchmark orchestration. Reviewed uses pass argument
lists, do not use `shell=True`, and are either gated actions or local inspection
commands. The destructive path is additionally protected by action-token,
two-step confirmation, path containment, Trash, and `ollama rm`.

### Bandit SQL string construction findings

Findings in dashboard CSV/database code are false positives. Table and field
names come from static allowlists such as `TABLE_FIELDS`, values are parameterized,
and unknown table names are rejected.

### Bandit hardcoded password/token findings

Reviewed hits were test fixtures (`test-token`, `fixture-token`, local URLs with
`user:secret`, etc.) or empty/default local values. These are intentionally used
to verify sanitization and action-token behavior.

### Bandit assert findings

Assertions are in tests and accepted as standard pytest/unittest style.

- Basic-auth URL hits are sanitization fixtures in tests.

  not tracked secrets.
