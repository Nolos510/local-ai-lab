  - `python -m pytest -q`

- Dashboard smoke commands work:
  - `python apps/model-dashboard/run_dashboard.py init-db --reset --with-fixtures`
  - Imported 4 `models`, 4 `model_runs`, 4 `eval_scores`, and 4 `decisions`.

## What Failed

- The first sandboxed `python -m pip install -e ".[dev]"` attempt failed because build isolation needed `setuptools>=61` and the sandbox could not resolve the package index. The same command passed once package-index access was allowed.
- The first sandboxed dashboard server start failed with `PermissionError: [Errno 1] Operation not permitted` while binding `127.0.0.1:8765`. The server started successfully once localhost bind permission was allowed.
- Unprivileged localhost `curl` probes could not connect across the sandbox boundary. The same probes returned HTTP `200` once localhost probe permission was allowed.
- Running `python apps/model-dashboard/run_dashboard.py report` rewrites the tracked fixture report timestamp. The command succeeds, but it dirties the worktree unless the timestamp is restored or the output path is changed.

## What Was Fixed

- No source-code fixes were required.
- Restored the tracked fixture report timestamp after the smoke run so the only intentional repo change from this pass is this integration review note.
- Created `docs/lab-notes/v0.1-integration-review.md`.

## Remaining Issues

- Fresh editable installs may need package-index access, or a pre-cached `setuptools>=61`, because the project uses PEP 517 build isolation.
- The default dashboard `report` command writes to a tracked fixture report and refreshes its generated timestamp. Future smoke checks should write to an ignored temporary report path or make the fixture report deterministic.
- Localhost server checks require elevated bind/probe permission in this Codex sandbox. This appears environmental, not an application failure.
- There is still no single QA command that runs the full dashboard smoke sequence end to end.

## Recommended Next Sprint

- Add a small local QA smoke script that runs tests, fixture import, report generation to an ignored path, and a localhost server probe on an available port.
- Adjust dashboard report smoke guidance so routine validation does not dirty tracked fixture artifacts.
- Start the next local-first evaluation harness work only after the v0.1 dashboard validation path is one-command reproducible.
