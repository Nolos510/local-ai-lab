# v0.4 Radar Candidate Dashboard

Date: 2026-06-03

## Summary

v0.4 adds a local candidate registry and a Radar Candidates page to the existing
Local Model Performance Dashboard. The page makes radar output visible without
turning candidate claims into eval scores.

## Implemented

- Added `data/model_registry/candidates.csv` as the normalized candidate source.
- Added `/radar` to `apps/model-dashboard`.
- Added candidate filters for search, status, family, and runtime.
- Linked registered benchmark run IDs to a local artifact detail page.
- Added smoke coverage for `/radar`.

## Registry Scope

The initial registry includes:

- `Qwen3-Coder-30B-A3B-Instruct-MLX-4bit`, linked to the first failed-runtime
  benchmark artifact and still marked `ready_for_eval`.
- `Model Atlas 7B`, marked `watchlist` from approved local source packet notes.
- `Model Boreal 13B`, marked `ready_for_eval` from approved local source packet
  notes.

Candidate records are not imported into `eval_scores`, final labels, or
dashboard decisions. Only scored local benchmark outputs should use the dashboard
CSV import path.

## Runtime Status

The first scored Qwen retest is still blocked until the LM Studio local endpoint
responds. On 2026-06-03, `http://127.0.0.1:1234/v1/models` did not accept a
local connection in this environment.

## Safety Posture

- No web fetching or web research.
- No cloud APIs or secrets.
- No model downloads.
- No runtime dependencies added.
- Candidate-only records remain separate from evaluated model scores.
