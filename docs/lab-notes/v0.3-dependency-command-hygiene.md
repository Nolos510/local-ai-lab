# v0.3 Dependency and Command Hygiene

Date: 2026-06-03

## Finding

AI Lab OS can keep the v0.3 local benchmark harness stdlib-only.

The expected harness work is command parsing, launching already-installed local
tools, capturing stdout/stderr, writing JSONL raw responses, writing dashboard
CSV imports, producing Markdown reports, and managing temporary files. Python's
standard library covers those needs with modules such as `argparse`, `csv`,
`json`, `subprocess`, `pathlib`, `tempfile`, `time`, and `sqlite3`.

## Guardrail

If Harness Builder proposes dependencies, challenge them before accepting:

- What exact capability is missing from the standard library?
- Is this runtime code or only test/developer tooling?
- Does it add network, cloud/API, model download, credential, binary, or heavy
  transitive dependency risk?
- Can the first v0.3 version ship without it?

The default answer for v0.3 is no new runtime dependencies.

## Setup Flow

Keep setup docs aligned on this flow:

```bash
python3 -m venv .venv
source .venv/bin/activate
python --version
python -m pip install --upgrade pip
python -m pip install -e ".[dev]"
python -m pytest -q
```

Use `python3` to create the venv. Use `python` and `python -m ...` after
activation so commands resolve through `.venv`. `pytest` belongs in the `dev`
extra, not runtime dependencies.
