# v0.3 Validation Checklist

Date: 2026-06-03

## Goal

Define the validation gate for the v0.3 benchmark-to-dashboard workflow before
Harness Builder lands.

This checklist keeps the existing dashboard smoke path blessed, defines the
tests expected for harness-generated dashboard CSVs, and records the benchmark
output commands that Harness Builder should make real.

```bash
python3 scripts/model_dashboard_smoke.py
```

## Harness CSV Import Tests

When Harness Builder lands, add automated tests that use a deterministic harness
fixture output directory with this layout:

```text
dashboard-import/
  models.csv
  model_runs.csv
  eval_scores.csv
  decisions.csv
metadata.json
raw_responses.jsonl
evidence.md
report.md
```

### Positive Import Tests

- [ ] Every expected dashboard CSV exists.
- [ ] CSV headers exactly match `model_dashboard.csv_io.TABLE_FIELDS`.
- [ ] Importing generated CSVs into a fresh temp SQLite database succeeds:

```bash
python3 apps/model-dashboard/run_dashboard.py import-csv \
  --db /private/tmp/ai-lab-os-harness-dashboard.sqlite \
  --models /private/tmp/ai-lab-os-harness-output/dashboard-import/models.csv \
  --runs /private/tmp/ai-lab-os-harness-output/dashboard-import/model_runs.csv \
  --scores /private/tmp/ai-lab-os-harness-output/dashboard-import/eval_scores.csv \
  --decisions /private/tmp/ai-lab-os-harness-output/dashboard-import/decisions.csv
```

- [ ] Imported row counts match the harness fixture manifest.
- [ ] Foreign key links are intact:
  - every `model_runs.model_id` links to `models.id`;
  - every `eval_scores.run_id` links to `model_runs.id`;
  - every `decisions.model_id` links to `models.id`.
- [ ] Every score dimension is numeric and between `0` and `100`.
- [ ] Blank `total_score` values are accepted and dashboard-calculated.
- [ ] Provided `total_score` values equal the documented aggregate, currently
  the mean of the eleven score dimensions unless the harness documents another
  aggregate.
- [ ] Blank `final_label` values are accepted and dashboard-suggested.
- [ ] Provided `final_label` values are valid dashboard labels.
- [ ] `model_runs.run_notes` includes:
  - `benchmark_run_id`;
  - `prompt_set_id`;
  - `rubric_version`;
  - raw artifact path or relative artifact pointer.
- [ ] Generated dashboard report succeeds from the imported database:

```bash
python3 apps/model-dashboard/run_dashboard.py report \
  --db /private/tmp/ai-lab-os-harness-dashboard.sqlite \
  --out /private/tmp/ai-lab-os-harness-output/dashboard-report.md
```

- [ ] The generated report includes the model name, final label, score, decision,
  and best use case.
- [ ] CSV export from the imported database succeeds and can be imported into a
  second fresh temp database.

### Negative Import Tests

- [ ] Missing dashboard CSV file fails clearly.
- [ ] Missing required column fails clearly.
- [ ] Broken foreign key fails.
- [ ] Score below `0` or above `100` fails.
- [ ] Invalid `final_label` fails.
- [ ] Invalid `keep_installed` value fails.
- [ ] Required fields such as `model_name`, `date_tested`, `backend`,
  `decision`, and `created_at` cannot be silently omitted.

### Privacy And Safety Tests

- [ ] Raw model responses stay in `raw_responses.jsonl`, not in dashboard CSV
  summary rows.
- [ ] Dashboard CSVs contain only normalized summary fields plus local artifact
  pointers.
- [ ] Harness output paths are local paths under `data/eval_results/` or an
  explicit temp directory.
- [ ] No API keys, cloud calls, model downloads, or web fetches are required for
  fixture generation or dashboard import validation.

## Dependency And Command Hygiene

- [ ] Harness implementation uses only Python standard library modules unless
  a dependency passes the review gate in `AGENTS.md`.
- [ ] Any proposed dependency documents the missing stdlib capability, runtime
  vs dev scope, transitive risk, and why v0.3 cannot ship without it.
- [ ] No cloud/API SDKs, model download packages, credential helpers, or heavy
  data/CLI frameworks are added for v0.3.
- [ ] `pyproject.toml` keeps runtime `dependencies = []`; pytest remains in the
  `dev` extra.
- [ ] Setup docs continue to use `python3 -m venv .venv`, then activated
  `python -m pip ...` and `python -m pytest -q`.
- [ ] Validation commands avoid global `pip`, global `pytest`, tracked report
  outputs, and ad hoc one-off command sequences.

## v0.3 Exit Criteria

- [ ] Blessed smoke path passes.
- [ ] Harness fixture output is deterministic and local-only.
- [ ] Raw benchmark artifacts validate.
- [ ] Harness-generated dashboard CSVs import into a fresh SQLite database.
- [ ] Dashboard report generation from imported harness data passes.
- [ ] Negative CSV contract tests prove bad harness output fails loudly.
- [ ] Docs name the exact validation commands and keep temp/generated outputs
  out of tracked paths.
- [ ] Dependency and command hygiene checklist is complete.
